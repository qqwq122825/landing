# LANDING HUB · 总站

一个根域名管理多个客户项目。此目录是独立新项目，原 `landing` 单站保持原样。

## 给后续开发者与 AI

先阅读 [AGENTS.md](AGENTS.md)。新增或仿照落地页模板时，按 [AI 新增落地页模板规范](AI_新增落地页模板规范.md) 执行：先核查参考站的实际多语言能力，再复刻布局 / 交互，接入公共 Pixel、下载入口、统计与逐账号模板权限，并逐项验收。语言菜单存在不等于整页已翻译；现有两款模板的语言缺口也已在规范中记录。

**复刻不是只还原外观：每个新模板须在同一次交付中接入并验证本站预设的 `PageView` / `DownloadClick` 公共代码。** 预设的是事件逻辑，Pixel ID 由各项目用户填写；无需用户另贴 JS，也不沿用参考站的 ID。

## 代码仓库

本目录为 Git 仓库根目录，远端为 [qqwq122825/landing](https://github.com/qqwq122825/landing)，主分支为 `main`。提交包含程序、模板资源、测试与开发规范；`runtime/` 仅保留 `.gitkeep`，本地环境配置、密钥、数据库、日志与压缩包均排除。

仓库当前公开。不要把客户账号、生产凭据或数据库加入版本控制；正式部署时设置独立管理员密码，勿沿用文档中的安装默认值。推送 GitHub 只更新代码仓库，不代表网站已部署。

## 总站 UI 与直接 Git 部署

总站使用 **Tabler 1.5.1（Bootstrap 组件）+ 原生 JavaScript + PHP**。表格、卡片、表单、菜单、弹窗、提示与进度条使用组件库，不再维护自绘控件；子账号后台和落地页保持独立。官方资料：[Tabler 安装文档](https://docs.tabler.io/ui/getting-started/installation)。

没有 Vue / Vite，也没有 `npm install`、`npm run build` 等生产部署步骤。固定版本的 CSS / JS 与许可证位于 `public/assets/vendor/tabler-1.5.1/`，随 Git 一起提交，浏览器不请求外部 CDN。业务 HTML / CSS / JS 修改后直接生效，不需要重新编译。Node 只用于可选的本地启动和自动测试。

**部署入口：[Git 部署指南](deploy/README.md)**，包含首次安装、宝塔设置、旧站迁移、日常更新和验收。

首次在新目录克隆：

```sh
git clone --branch main --single-branch https://github.com/qqwq122825/landing.git landing-hub
cd landing-hub
php bin/check.php
```

然后将站点 Web 文档根目录设为这个仓库的 **`public/`**，按指南配置 PHP、数据目录权限、HTTPS 与伪静态，再访问 `/install.php` 初始化。`bin/check.php` 是只读预检，不读数据库内容、不创建文件。

已安装且目录已绑定本仓库时：备份后在程序根目录执行 `git pull --ff-only origin main`。保留私有数据、密钥和 `install.lock`，无需重装；遇到本地修改先核对差异，不强制覆盖。推送 GitHub 不会自动触发服务器拉取。

## 入口设计

```text
https://你的域名/                       总站登录 / 项目总览
https://你的域名/p/随机项目编号           该客户的落地页
https://你的域名/p/随机项目编号/admin     该客户的独立后台
https://你的域名/p/随机项目编号/dl        跳转该项目配置的下载地址
```

开户时生成 **9 位随机项目编号 + 无固定前缀的 10 位随机账号 + 10 位随机密码**；账号使用小写字母和数字，密码包含大小写字母与数字，避开易混淆字符，由 PHP `random_int()` 生成。客户不使用总站的默认凭据，已有账号和密码在更新时保留；主动重置客户密码时使用新的 10 位规则，账号不变。总站管理员的密码规则保持原样。同一套模板资源供全部项目共享，不为每个客户复制整套网站。

### 已实现

- 总站：项目总览、搜索、状态筛选、开户、修改项目名称与内部备注、暂停 / 恢复、重置客户密码、汇总访问分析、操作日志。
- 总站「模板管理」：集中展示全部模板，按名称或编号搜索，手机 / 桌面真实预览，查看使用数量、开放账号数量与关联项目。无项目也能预览；预览使用模板原始显示名，不创建账号、不改动客户配置、不记录访问、不启用 Pixel。模板目录与全局预览仅限总站登录后访问。
- 客户：沿用原版深色窄版后台，7 项统计、趋势、国家 / 设备分布、分页明细；独立登录，只管理所属项目的显示名、图标、下载地址、模板、Pixel ID。总站保留浅色管理界面。
- 两套实际落地页模板：Feiyue / ReelShort、DPTV / MinuteDrama，带手机框预览，确认后切换；总站在开户与项目管理中逐账号勾选开放范围，客户仅显示、预览和使用已开放模板。
- 数据：累计 / 今日访问、独立 IP、下载点击、访问转化率、可见停留时长、7 / 30 天趋势、分页访客明细。
- 总站可按需查看客户密码并一键复制落地页地址、后台地址、账号和密码。登录仍校验密码哈希，另存 AES-256-GCM 加密交付副本；普通列表、客户接口及日志不返回密码。旧账号仅存哈希的，需主动重置一次才能再次查看，更新不会自动改密。暂停、恢复、重置会撤销旧客户会话。
- 真实 IP / 地区：沿用已验证的 Cloudflare 可信代理识别。直接本地访问显示 127.0.0.1，地区为空属于预期。

### 当前版本边界

这是可运行的 **单机 MVP**：一个总站角色，每个项目一个客户账号。尚未实现套餐计费、到期续费、邀请子成员、一个客户管理多个项目、自定义域名、2FA、自动邮件交付和生产级队列。没有对大并发作容量承诺；多节点和大量事件应迁移数据库及事件采集链路后压测。

原有模板来自当前工作区的单站资源；本站设计为独立实现。没有获取参考站服务端代码或尝试其总站密码。原单站历史数据尚未迁入总站。模板中的宣传文案、剧图、商店文字与法律信息沿用原样，正式投放前应替换成项目实际内容。

## 本地开发（可选）

在自己的克隆目录内执行：

```sh
php bin/check.php
# 仅限尚未安装的新本地实例，默认 mtx / mtx123：
php bin/setup.php
# 正式环境请在网页安装时设置独立密码，或 CLI 使用 --random-password。
HUB_DEV=1 php -S 127.0.0.1:57600 -t public router.php
```

浏览器打开 <http://127.0.0.1:57600/>。也可使用 `npm run dev`，会自动设置本地环境；Node 仅用于这个便捷启动和测试，不是生产依赖。内置开发服务器只监听本机，不用于正式部署。

初始化凭据写入私有数据目录内的 `初始账号.txt`，勿提交或公开分享。已有实例不要重新初始化；默认不会创建演示项目，开发演示可单独传 `--demo`。指定独立 `HUB_DATA_DIR` 可隔离测试数据与已有项目，CLI 和服务进程必须使用同一个值。

PHP 最低版本 8.1；生产请选用仍受维护的 PHP 版本，参见 [PHP 官方支持表](https://www.php.net/supported-versions.php)。安装与扩展要求见部署指南。

## 伪静态路由

需要配置：`/p/项目编号`、`/p/项目编号/admin` 和 API 都由 `public/index.php` 统一处理，不为客户创建真实目录。

- **Nginx / 宝塔**：站点运行目录设为 `public/`，将 `deploy/nginx-rewrite.conf` 内容放入该站点的伪静态配置；另行启用 PHP 解析。
- **Apache**：已提供 `public/.htaccess`，启用 `mod_rewrite` 并允许该目录使用规则。
- **本地测试**：`npm run dev` 已启用 `router.php`，无需额外配置。

这些规则只处理应用路由；Cloudflare 保持现有代理、防护设置。部署包不会自动修改服务器配置。

- [Git 部署指南](deploy/README.md)：服务器拉仓库即可获取完整代码和本地 UI 资源；首次配置完成后不再上传 `dist` 或补丁包。

- 新项目 APK 下载地址默认留空，客户自行填写；没有默认下载链接。原账号、项目编号和客户配置在代码更新时保留。

### Cloudflare 与缓存

保持现有代理和防护设置；本项目仅使用请求头读取 IP 与地区，不涉及关闭 DDoS / WAF。Cloudflare 的访客 IP 来自 `CF-Connecting-IP`，国家来自 `CF-IPCountry`；地区 / 城市由访问者位置标头提供。官方字段说明：[Cloudflare HTTP headers](https://developers.cloudflare.com/fundamentals/reference/http-headers/)。

程序先核对直接连接的代理地址是否位于 Cloudflare CIDR，才采信这些标头。任意访客传入同名标头不视为可信。若 Nginx 已先改写 `REMOTE_ADDR`，将原代理地址通过服务端 `TV_PROXY_PEER` FastCGI 参数传入（参考配置里的注释）。经 Tunnel 或其他内部代理时需按真实拓扑另行适配，勿直接全量信任转发标头。

- 登录页、后台 HTML、全部 API、带签名访问编号的项目 HTML 与 `/dl` 使用 `no-store`；Cloudflare 避免为这些路径设置覆盖源站头的“缓存所有内容”规则。
- 仅 `/themes/` 共享图片与样式适合长期静态缓存。后台 CSS / JS 使用内容哈希版本查询参数。
- 源站访问限制、TLS 和边缘规则需另外验收，详见 [保护源站](https://developers.cloudflare.com/fundamentals/security/protect-your-origin-server/)。该本地版本不是抗流量攻击压测报告。

### Pixel 与域名验证

根域名验证由总站统一维护；在 PHP-FPM 配置 `HUB_FACEBOOK_VERIFY` 后，根域名登录页输出验证 meta。Pixel ID 输入区仅在子账号后台显示，总站项目管理不重复填写；已保存的项目 Pixel ID 保留。

两套落地页统一内置 Meta Pixel。子账号保存有效数字 ID 后，新打开的实际落地页自动初始化该 ID，并发送一次 `PageView`（页面访问）；点击 `.download-link` 下载入口时发送 `DownloadClick`（自定义事件）。动态弹窗中的下载按钮同样生效，普通搜索、语言选择和模板预览不发送这些事件。重复加载项目设置不会重复初始化或重复发送页面访问。

Pixel ID 默认留空，留空 / 无效 ID 不加载 Meta 脚本。后台不引用该脚本，预览明确禁用上报；浏览器 DNT / GPC 仍会停用追踪。移除此前必须为 `true` 的同意开关，常规启用无需另外添加 JS 或配置。若部署自行接入同意组件，可在脚本运行前明确设置 `window.HUB_TRACKING_CONSENT = false` 暂停初始化，取得同意后设为 `true` 并派发 `tv:settings`（detail 为 `window.HUB_PAGE`）；完整的授权撤回 / Cookie 管理由该组件实现，本次未附带 CMP。

保存、修改或清空 ID 对之后打开 / 刷新的落地页生效，已打开的页面请重新加载。`DownloadClick` 统计点击，不代表 APK 下载完成或安装完成；安装 / 首次启动归因需要应用端事件接入。网络、广告拦截或浏览器隐私设置可能影响 Meta 接收；应使用真实 ID 在 Meta 事件管理工具验证。上线时同步配置符合业务实际的隐私告知及适用的同意流程。

第一方访问统计会记录访客 IP、粗略地区、设备及可见停留时间，不记录请求中的任意账号信息。请根据业务和地区制定隐私告知、保留期及删除流程。本版本未自动执行数据过期清理。

## 备份与管理账号恢复

```sh
# 运行时设置与 PHP-FPM 保持一致；备份存到公开目录之外。
php bin/backup.php --output=/path/to/private-backups
# 此操作生成总站新随机密码，旧密码和原有会话立即失效：
php bin/admin-password.php --username=mtx
```

网页重新安装需先在服务器文件管理中删除数据目录的 `install.lock`。入口开放后请立即完成安装；确认勾选“保留数据并更新管理员”才会变更已有主管理员，其他客户及统计原样保留，旧总站会话失效。程序会先生成 `before-install-*.sqlite` 快照，安装成功后重新生成锁。日常 Git 更新保留安装锁，不运行重新安装流程；没有任何在线删锁接口。详见 [网页安装说明](docs/网页安装说明.md)。

备份使用 SQLite `VACUUM INTO` 一致性快照；另外备份数据目录的 `secret.key`、`credentials.key` 与部署环境配置。交付密钥与数据库分开妥善保管，恢复时必须匹配；密钥丢失不会自动重新生成覆盖旧密钥。不要只复制在线 WAL 模式的主数据库文件。恢复时暂停写入，以快照替换目标 `hub.sqlite`、移除对应旧 WAL / SHM 并恢复文件权限；停止服务后操作，保留恢复前完整副本。恢复后清理会话并重新登录。

## 客户交付信息与模板权限

- 在项目列表点“查看密码”或“复制交付”；详情页也有入口。仅总站使用带 CSRF 的独立接口按需读取；查看操作留痕但不记密码。弹窗关闭、页面转后台或 60 秒超时后清空页面中的交付内容，剪贴板由用户自行管理。
- 首次使用自动增加 `password_cipher` 和 `allowed_templates` 两个字段，不清空数据库、不删除安装锁。新账号及主动重置的客户密码加密保存；既有哈希账号提示先重置一次，不尝试恢复哈希。
- OpenSSL AEAD 调用参考 [PHP 官方文档](https://www.php.net/manual/en/function.openssl-encrypt.php)。独立 32 字节随机密钥位于私有 `runtime/credentials.key`，每次加密使用独立 nonce，密文绑定项目和账号。应限制服务器文件权限、保护总站账号，并使用 HTTPS。
- 模板开放范围默认保留现有两款。至少开放一款；取消当前使用模板时自动换成首个勾选项。已撤回模板的客户预览和保存接口也会检查权限。静态资源继续共享，不属于私有素材保护系统。
- 历史功能记录见 [账号交付与模板权限更新说明](docs/updates/账号交付与模板权限更新说明.md)；当前部署方式见 [Git 部署指南](deploy/README.md)。
