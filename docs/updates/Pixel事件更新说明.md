## 使用方式

1. 进入子账号后台的 Facebook Pixel，填写属于该项目的有效 Meta Pixel 数字 ID 并保存。
2. 重新打开 / 刷新实际落地页 `/p/项目编号`，不要使用模板预览页测试 Meta 接收。
3. 页面自动初始化项目 Pixel 并发送一次 `PageView`。每次点击实际下载入口，发送一个自定义事件 `DownloadClick`，包含动态弹窗里的下载按钮。
4. 在 Meta 事件管理工具的「测试事件」确认页面访问和下载点击接收。该配置不要求客户另粘贴 JS、填总站 Pixel 或设置额外启用变量。

两套现有模板使用同一个项目级事件脚本。脚本异步加载前的事件进入队列，重复的设置通知不重复初始化和发送 PageView；下载监听使用捕获阶段，兼容 JS 跳转与动态按钮。

## 不上报的情况与统计口径

- ID 留空或格式无效：不加载第三方 Pixel。修改、清空 ID 对之后打开 / 刷新的页面生效。
- 总站后台、子后台、全局模板预览、项目模板预览：不发送 Pixel 事件。
- 普通搜索、语言选择等非下载控件不发送 DownloadClick；浏览器 DNT / GPC 隐私选择仍保留。
- 已有部署如果明确设置 `HUB_TRACKING_CONSENT = false`，仍会暂停初始化；默认未设置此变量时，填写有效 ID 即启用。与独立访客同意组件整合的方法见 README。
- `DownloadClick` 只表示下载点击，不表示文件下载完成或 App 安装成功。广告拦截、网络或隐私设置会影响实际送达；纯浏览器事件不承诺所有点击均被 Meta 接收。
- 下载点击按每次点击发送，本站后台转化率则按点击过下载的访问去重，两个口径有区别。

## 部署

将 `总站_Pixel事件更新补丁.zip` 解压覆盖到总站程序根目录（包含 app、public、runtime 的那一层）。保留 runtime、数据库、密钥与 install.lock，无需重装或删锁。

更新包含之前的账号交付、模板权限与模板管理补丁。落地页共享 Pixel 脚本增加内容哈希版本号，以便刷新后加载新代码；若部署配置了特殊缓存规则，请刷新相关缓存。上线时同步核对隐私告知和适用的访客同意流程。

## 后续更新：DNT / GPC 不再自动停报

按当前需求，总站全部实际落地页共用的 `brand-settings.js` 与 `collector.js` 不再使用浏览器 DNT / GPC 信号决定是否停报。该修改同时覆盖项目 Pixel 的 PageView / DownloadClick 以及本站访问、停留、下载点击统计；后台说明与新增模板规范同步更新，旧的独立单站目录未改动。

- 正常使用只需子后台保存有效 Pixel ID，无须启用额外开关。空 / 无效 ID、后台、项目预览、全局预览继续隔离；重复配置通知不会增加 PageView。
- 保留原先仅供代码接入的 `HUB_TRACKING_CONSENT === false` Pixel 暂停变量，默认未设置，不影响常规上报；它不是后台需要手动打开的选项。
- 两个公共脚本均使用内容哈希版本 URL，Git 更新后刷新实际落地页即可加载新逻辑，已经打开的页面需重新加载。保持数据库、安装锁、账号和 Pixel ID 原值，不涉及 Cloudflare 配置。
- 128 项自动测试及改动 PHP / JS 语法、只读预检通过。新增第一方采集器 VM 测试，覆盖信号分别 / 同时开启、浏览与停留、点击、预览隔离和 Beacon 的 fetch 回退。
- 独立本地浏览器测试将 DNT / GPC 同时设为开启，并使用本地 SDK 替身：两款实际模板各初始化一次、各产生一次 PageView，下载入口与弹窗点击触发 DownloadClick，第一方数据各记录一次访问和一次去重转化；四个全局 / 项目预览入口均无 Pixel 调用、无新增访问。浏览器未记录错误或警告。
- 本次未连接真实 Meta 账号，未代为部署线上；发起事件不等于 Meta 接收成功，也不绕过浏览器拦截或代表已满足适用地区的隐私要求。
