# 总站项目删除 · 2026-09-21

## 操作入口

项目总览 → 全部项目 → 每行操作区的红色 **删除**。

弹窗显示项目名、`/p/项目编号` 与影响范围。必须手动输入完全一致的项目编号，才会启用“永久删除”。取消、关闭或重新打开都会清空确认输入；提交期间禁止重复提交和关闭弹窗。

这是应用层永久删除，没有回收站 / 撤销入口。删除前请按 [备份说明](../../README.md#备份与管理账号恢复) 保存数据库快照与匹配的密钥。暂时停用项目使用现有的“暂停”；备份文件不随项目删除自动清理。

## 删除范围

- 删除所选项目的客户账号、密码哈希、加密交付副本、品牌 / Pixel / 下载配置，以及访问和事件记录。
- 原落地页、下载入口、子账号后台、预览和统计 API 返回项目不存在；原客户登录会话不再获得该项目数据。
- 总站项目数、运行中数量、统计汇总、模板使用 / 开放数量按现有项目重新计算。
- 其他客户、总站账号、共享模板文件、私有密钥、安装锁及备份保持原样。
- 操作日志保留。历史项目关联显示“已删除 /p/编号”，删除操作记录管理员、时间和项目名称，不记录密码。

## 服务端与数据兼容

- 入口为总站 `POST /api/projects/{slug}/delete`，JSON 中必须提供完全匹配的 `confirmSlug`。服务端验证总站登录、CSRF 与 Origin；客户接口没有删除入口。
- 删除账号、访问记录、事件、编号停用记录及审计在同一 SQLite 事务内完成；任一步失败全部回滚。
- 新增 `deleted_projects` 表，只保留内部 ID、项目路径编号、删除时间，用于停用编号，不保存客户配置或密码。已有客户更新后原样保留；仅管理员明确确认删除时才删除数据。
- 新项目分配 ID 时兼顾现有项目和已停用 ID，路径编号同样避开已删除项目，避免旧访问令牌或旧审计关联到新客户。
- 事件入库前在事务中再次检查项目存在与状态，处理删除或暂停期间的滞后请求。

## 验证与部署

- 自动测试覆盖总站权限、客户越权、CSRF / Origin、编号校验、失败回滚、数据隔离、历史日志、统计更新、最后一个项目删除后重新开户，以及旧会话 / 访问令牌失效。
- 前端逻辑测试覆盖确认输入、取消、重复提交、请求失败重试、登录过期和删除成功但列表刷新失败。
- 浏览器仅在独立测试实例验证红色操作按钮、桌面 / 390px 手机弹窗、错误 / 正确编号的按钮状态与取消保留；完整删除通过隔离数据的接口测试完成，没有操作现有客户项目。
- 备份后按 [Git 部署指南](../../deploy/README.md) 拉取，刷新后台即可，无需编译或重新安装。运行时自动增加编号停用表；保留 runtime、密钥及 install.lock。
- 本地验证不代表线上已部署，服务器拉取后生效。
